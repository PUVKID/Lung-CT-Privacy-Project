# 연결 공격·완료 캐시·공격 진행 표시 수정

| 항목 | 현재 동작 | 해석 |
|---|---|---|
| 연결 gallery | 고유 source_id마다 원본 대표 1개, canonical 우선 | 복사본이 비교 후보 수를 부풀리지 않음 |
| 연결 정답 | Top-k의 source_id 또는 patient_id 일치 | 같은 원본의 다른 사본도 정답. 모든 query는 유지 |
| 완료 캐시 | 복원 공격은 run_id, 조건 결과는 run_id·프로토콜·조건 확인 | 불일치·누락은 오류로 중단하고 원파일 보존 |
| 공격 진행 | 복원모델 학습·검증, 복원 평가, 연결·멤버십·셔플의 실제 처리 수를 기록 | 분류 회차·정확도와 분리. 같은 단계는 대체로 2초 간격, 완료/단계 전환 즉시 기록 |

증강 보조 연결 점수는 증강 query 행 기준입니다. 고유 gallery 원본 수와 query 수를 별도로 보고하며 증강이 독립 환자를 늘리지 않습니다. Top-k가 gallery 수보다 크면 실제 후보 수까지만 검색합니다. 같은 source_id의 환자 정보가 충돌하면 거부합니다.

화면에는 예를 들어 `원본 복원 평가 · conv1 · f16 · test · 처리 7 / 20`이 표시됩니다. 사진 한 장의 최적화가 끝나기 전에는 완료 수를 올리지 않습니다. 이것은 경과시간/남은시간 예측이나 가상 그래프 애니메이션이 아닙니다. 복원 공격은 분류가 끝난 뒤에도 오래 걸릴 수 있습니다.

작은 CPU 합성 재현과 API·화면 함수 검사를 사용했습니다. 실제 전체 17차 학습, 실제 복원 성능, 브라우저 클릭 검증을 수행했다는 뜻은 아닙니다. 12차·자료 이동·표본수·분할·블러 강도·모델 선정 기준을 바꾸지 않습니다. 정확도를 100% 미만으로 강제하지 않습니다.
